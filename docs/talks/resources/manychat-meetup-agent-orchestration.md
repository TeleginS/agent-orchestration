> [!abstract] Тезис доклада (одна мысль)
> Детерминированный harness — не костыль, а фундамент агента. **Граф выполнения** — лучший примитив, чтобы его выразить, но сила графа не в максимальной жёсткости, а в балансе «детерминированное vs креативность модели» — и важно понимать, где граф нужен, а где избыточен.

## План речи (тезисно)

### 1. Что такое агент и где в нём логика (~2 мин)
- Модель = «органы чувств», тулы = «руки», harness/стратегия = «мозг».
- Модель лишь предсказывает токен / tool-call; **порядок действий несёт harness**.
- Источник: [04:18]

### 2. Зачем harness, если модели умнеют (~2 мин)
- Ошибка **накапливается** с каждой итерацией + у ошибки есть **цена**.
- Кодинг-агенты: ошибка дешёвая (есть ревьюер). Фейсинговые: дорогая (деньги).
- 1% × N запусков **суммируется** → теряем пользователей.
- Вывод: кастомные агенты под задачу с guardrails, а не «голый» цикл.
- Источник: [15:38]

### 3. Эволюция архитектур: от цикла к графу (~5 мин)
- Цикл → ReAct → микроагенты (оркестратор + узкие подагенты).
- Почему микроагенты буксуют: оркестратор забывает, дублирование эксплорейшена.
- Метафора: «узкий коридор вместо широкой комнаты».
- Источник: [19:41]

### 4. Граф выполнения как примитив (~5 мин)
- solver + evaluator со строгим `if`: из цикла не выйти, пока эвалюатор не доволен.
- Чекпоинты: сериализация → дебаг и отказоустойчивость.
- GOAP (отдельно упомянуть): действия с precondition/action/side-effect, план перестраивается A*.
- Источник: [19:41]

### 5. Граф vs недетерминированность моделей (~5 мин)
- Вершина = функция (`input → действие → output`), рёбра = условия на output.
- Модель влияет на переходы, но мы контролируем **правила** (метафора игры в шахматы).
- **Детерминированные вершины**: чем больше шагов без LLM — тем лучше.
- Баланс: слишком жёсткие ограничения делают умную модель глупой (`grep` vs примитивный поиск).
- Источник: [34:14]

### 6. Минусы графов: когда граф избыточен (~5 мин)
- Usability: граф сложнее рефакторить, чем код.
- Ограничение креативности → «минус 10% качества», оркестратор часто находит путь короче.
- Графы тюринг-полны — вопрос гранулярности и эвалюации.
- **Масштаб кодовой базы:** на маленьком проекте граф строится и читается легко; на большом объёме кода (свой опыт с Manychat) теряется обзорность, гранулярность вершин размывается, граф перестаёт ложиться на реальный flow. Поэтому граф нужно **тюнить и оптимизировать** (какие вершины выносить, что детерминировать, где резать), а не просто выгрузить один раз.
- Следующий шаг: self-evolving / оптимизаторы (DSPy).
- Источник: [40:05]

### 7. Живой пример: граф моего проекта (~10 мин) — своя часть
- Выгрузить граф текущего flow разработки из собственного проекта.
- Показать, как его улучшать, на что смотреть.
- Пример прогона такого графа на задаче.

## 📚 Ресурсы — стоит исследовать

> [!note] Сейчас опираюсь только на Koog (видео выше). Ниже — кандидаты на добор. Для каждого: выжимка «что внутри» → чтобы решить, брать или нет.

### 1. Anthropic — Building Effective Agents (Dec 2024) ⭐ обязательно
→ https://www.anthropic.com/engineering/building-effective-agents
- **Что внутри:** канон. Разводит **workflows** (предзаданные code paths) vs **agents** (LLM сам направляет процесс). 5 паттернов: prompt chaining, routing, parallelization (sectioning/voting), **orchestrator-workers**, **evaluator-optimizer**.
- **Зачем для доклада:** evaluator-optimizer = тот самый solver+evaluator граф из видео; orchestrator-workers = микроагентная архитектура. Базовый словарь, без него никуда.

### 2. CloudWeGo Eino — Agent or Graph? (May 2026) ⭐
→ https://www.cloudwego.io/docs/eino/overview/graph_or_agent/
- **Что внутри:** прямое сравнение Agent vs Graph как двух парадигм. Таблица различий (core driver, input, state, runtime), исторический контекст (LangChain→LangGraph→ReAct). Ключевой вывод: **лучшая точка интеграции — «инкапсулировать Graph как Tool агента»**.
- **Зачем:** готовый каркас для объяснения «граф vs автономный агент» + идея graph-as-tool — прямо ложится на твой тезис.

### 3. Elementum — Are AI Agents Deterministic? ⭐
→ https://www.elementum.ai/blog/are-ai-agents-deterministic
- **Что внутри:** агенты недетерминированы (temperature=0 не спасает — floating point, silent updates). Убойная цифра: **10 шагов по 95% точности = 59.9% надёжности цепочки (0.95¹⁰)**. Тезис: агенты — governed components внутри детерминированного workflow, а не сам workflow.
- **Зачем:** готовая математика «почему ошибка накапливается» + enterprise-аргумент (SOX, EU AI Act) для фейсинговых сценариев.

### 4. GitHub — What is AI agent orchestration?
→ https://github.com/resources/articles/what-is-ai-agent-orchestration
- **Что внутри:** оркестрация = **control layer** (governance, state management, policy-as-code, human-in-the-loop). Детерминированные чекпоинты и state store для resume/recovery. Паттерны: sequential, concurrent, group chat, handoff, magentic.
- **Зачем:** язык «control plane / checkpoint / approval gate» для enterprise-подачи; пример пайплайна Build → Code Review Agent → Security Agent → Test → Deploy.

### 5. LangGraph — Graph API overview
→ https://docs.langchain.com/oss/python/langgraph/graph-api
- **Что внутри:** практическая реализация графов: **State** (общее состояние) + **Nodes** (функции) + **Edges** (переходы, в т.ч. conditional). Компиляция, checkpointers, Pregel-подобные super-steps, recursion limits, встроенная визуализация графа, LangSmith для трейсинга.
- **Зачем:** конкретный инструмент «как графы делают на практике» + визуализация — ровно то, что сам планируешь показать на своём графе.

### 6. Anthropic — How we built our multi-agent research system (Jun 2025)
→ https://www.anthropic.com/engineering/multi-agent-research-system
- **Что внутри:** production multi-agent (orchestrator-worker) для Research. Уроки: «think like your agents», «**teach orchestrator how to delegate**» (без чётких task description агенты дублируют работу), «scale effort to query complexity». Честно про минусы: multi-agent ≈ **15× токенов** vs chat; token usage объясняет 80% вариации.
- **Зачем:** реальный кейс «когда multi-agent оправдан, а когда нет» + цифры по стоимости (противовес хайпу).

### 7. OpenAI Agents SDK — Orchestration & handoffs
→ https://developers.openai.com/api/docs/guides/agents/orchestration
- **Что внутри:** **handoffs** как first-class механизм маршрутизации между специализированными агентами; guardrails как first-class. Паттерн triage-agent → specialist (billing/refund). «Give each specialist a narrow job; split only when the next branch needs different instructions/tools/policy».
- **Зачем:** пример декомпозиции на узких агентов + approval/guardrails — совпадает с «микроагенты» из видео, но на конкретном SDK.

### 8. GOAP — Three States and a Plan: The AI of F.E.A.R. (Jeff Orkin, GDC 2006)
→ https://www.gdcvault.com/play/1013394/Three-States-and-a-Plan
- **Что внутри:** техника из game AI (популяризирована Джеффом Оркиным на F.E.A.R., 2005): агенты описываются только действиями (preconditions + effects), планер (A*) динамически ищет цепочку действий к цели — вместо ручной state machine на 2ⁿ состояний.
- **Зачем:** истоки GOAP для блока про планирующих агентов. Rod Johnson (создатель Spring) перенёс подход на LLM-агентов — см. видео [26:59]. Точное название его фреймворка в транскрипте обрезано — уточнить отдельно.
